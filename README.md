# Travel Ready — задание 20

Travel Ready — настольный WPF-планировщик поездок для Windows. В нём можно составить маршрут, подготовить список багажа, распределить вес между пассажирами и проверить прогноз и готовность к отъезду. Новый профиль открывается с пустым планом без демонстрационных данных. Исходное решение открывается в Visual Studio 2022 через `TravelReady.sln`.

Текущий интерфейс устроен как двухстраничный редакционный разворот: слева находятся маршрут, шаблоны, вес, готовность и погода; справа — редактируемый реестр вещей. Светлая сиреневая основа `#F4F1F8`, сливовый `#3D294D` и коралловый `#D84C68` объединяют главное окно, вход и почтовые настройки. Для крупных заголовков используется Georgia, для полей и таблицы — Arial.

## Возможности

- Регистрация подтверждается шестизначным кодом из письма, действующим 10 минут и допускающим до пяти неверных попыток. Вход выполняется по адресу почты и паролю.
- Кнопка «Забыли пароль?» запрашивает код восстановления через Mail API. Случайный 16-символьный код действует 10 минут, допускает до пяти неверных попыток и используется один раз; повторные запросы ограничены одной минутой. При неуспешной отправке код отменяется.
- Пароли хранятся как PBKDF2-HMAC-SHA256 хеши с индивидуальной случайной солью. В SQL Server хранится только SHA-256 хеш кода восстановления, а не сам код.
- Поездки профилей разделены в SQL Server LocalDB. Изменения маршрута, вещей и прогноза сохраняются автоматически после небольшой задержки.
- Для вещей доступны категории, пассажиры, количество, вес, обязательность, статус, фильтры и поиск. Шаблоны для города, деловой поездки и активного отдыха учитывают длительность поездки.
- Панель готовности показывает общий вес, нагрузку пассажиров, остаток лимита и недостающие важные позиции; балансировщик распределяет вещи с учётом уже собранного веса.
- Погода загружается через WeatherAPI при наличии личного ключа или через Open-Meteo без него. Ключ вводится через «КЛЮЧ API» и защищается DPAPI отдельно от EXE; WeatherAPI использует HTTPS-запрос к `forecast.json` с прогнозом до семи дней. Ошибка по одному городу не скрывает доступные прогнозы для остальных; резервная оценка явно помечается как офлайн.
- Доступны ручной импорт и экспорт JSON, а также экспорт списка в CSV.

## Локальная база и переход с SQLite

Для запуска требуется установленный локальный SQL Server или SQL Server Express LocalDB. По умолчанию приложение подключается с учётной записью Windows к экземпляру `(localdb)\MSSQLLocalDB` и создаёт `TravelReadyDb`, если её ещё нет. Актуальный именованный pipe определяется автоматически. Сервер и имя базы можно переопределить переменными `TRAVELREADY_SQL_SERVER` и `TRAVELREADY_DATABASE_NAME`. Пользователю SQL Server нужны права на подключение и создание базы.

Схема разделяет профили, поездки, города маршрута, справочники, пассажиров, вещи, погоду и коды восстановления. Города хранятся по одному в `TripCities` с порядком следования. Ограничения внешних ключей не допускают привязать вещь к пассажиру другой поездки.

Если существует прежняя `%LOCALAPPDATA%\TravelReady\travelready.db` и целевая SQL-база ещё пуста, приложение импортирует данные SQLite в SQL Server. Исходный файл SQLite остаётся без изменений и не используется как рабочая база после переноса. Новые профили и поездки сохраняются в SQL Server LocalDB.

## Почта и секреты

Для регистрации и восстановления пароля нужен работающий отдельный Mail API с настроенной SMTP-доставкой. В окне входа можно указать адрес API и токен доступа; HTTPS обязателен для удалённого адреса, HTTP разрешён только для loopback. Приложение также может прочитать совместимые настройки текущего пользователя из RouteStudio или переменные `TRAVELREADY_MAIL_API_URL` и `TRAVELREADY_MAIL_API_TOKEN`. Сохранённый локально токен защищён Windows DPAPI. SMTP-пароль остаётся в процессе почтового сервера; исходники и сборка Travel Ready не содержат почтовых секретов.

Приложение принимает успешный ответ Mail API только после отправки запроса и не показывает успешную смену пароля до проверки кода. Изолированные тесты проверяют формат HTTP-запроса подменённым ответом. Реальная доставка через SMTP в этом прогоне не проверялась — её нужно отдельно проверить с собственным настроенным Mail API и почтовым ящиком.

## Сборка и проверки

Для сборки исходников требуется .NET 9 SDK и Visual Studio 2022 с поддержкой WPF либо командная строка Windows:

```powershell
dotnet build TravelReady.sln -c Release
dotnet run --project TravelReady.IntegrationTests -c Release
dotnet run --project TravelReady.UiSmokeTests -c Release
```

Последний прогон текущего исходного проекта: сборка без предупреждений и ошибок, интеграционные проверки 39/39, UI smoke 6/6. Подробности и границы этих проверок приведены в `TESTING.md`.

Диагностические события в `Debug` и `Trace` содержат коды событий и типы ошибок без почтовых адресов, паролей и ключей.

Автономный Windows x64 EXE с исправленным подключением находится в `../../CourseworkBuilds/20-TravelReady-r10-LocalDbFix/TravelReady.exe`. Программа получает актуальный именованный канал LocalDB через `SqlLocalDB.exe`, поэтому повторно подключается после автоматического перезапуска экземпляра. EXE включает .NET, но не включает SQL Server LocalDB, почтовый сервер или секреты. Повторить сборку можно командой `dotnet publish TravelReady/TravelReady.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`.
