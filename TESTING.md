# Проверки Travel Ready

Проверки ниже выполнены для текущего исходного проекта. Им нужен установленный и доступный SQL Server LocalDB: по умолчанию используется экземпляр `(localdb)\MSSQLLocalDB`, его текущий канал определяется автоматически. Тесты создают отдельные временные базы с уникальными именами; рабочую `TravelReadyDb` они не используют. Один сценарий миграции копирует прежний `%LOCALAPPDATA%\TravelReady\travelready.db` во временный каталог и проверяет перенос на копии; для полного прогона этот файл должен существовать, оригинал не меняется.

## Команды и результат

```powershell
dotnet build TravelReady.sln -c Release
dotnet run --project TravelReady.IntegrationTests -c Release
dotnet run --project TravelReady.UiSmokeTests -c Release
```

Последний прогон: сборка завершилась с 0 предупреждений и 0 ошибок; интеграционные проверки — **39 пройдено, 0 ошибок**; UI smoke — **6 пройдено, 0 ошибок**.

## Интеграционные проверки

Набор `TravelReady.IntegrationTests` проверяет:

- создание пустой SQL-схемы, правила адреса и пароля, регистрацию, вход, уникальность почты без учёта регистра и одноразовый код подтверждения регистрации;
- запрос восстановления пароля через `/api/mail/account-code` с назначением `password-reset` и bearer-токеном; старый сервер, не поддерживающий этот endpoint, не считается успешной отправкой;
- отсутствие кода для неизвестного профиля, хранение только хеша кода, запрет применения до подтверждения отправки, ограничение повторного запроса, истечение срока, блокировку после пяти ошибок, одноразовую смену пароля и отмену неотправленного кода;
- транзакционное сохранение поездки, восстановление городов, вещей, пассажиров и погоды, разделение данных профилей и обновление без дублирования;
- нормализованное хранение городов в `TripCities` и внешний ключ, который не позволяет привязать вещь к пассажиру другой поездки;
- импорт прежней SQLite-базы в отдельную SQL-базу с сохранением строк и порядка городов. Исходный SQLite-файл остаётся без изменений;
- адаптивные шаблоны багажа, резервную погоду и частичный отказ прогноза по маршруту;
- разбор ответа WeatherAPI и параметры запроса на подменённом HTTP-ответе без реального ключа.

## Интерфейс и автосохранение

`TravelReady.UiSmokeTests` открывает WPF-окно с тестовым профилем и временной SQL-базой. Проверены двухстраничная компоновка без обрезки панели готовности, пустое состояние нового профиля, автосохранение маршрута и добавленного предмета, создание городского шаблона и восстановление поездки после повторного открытия окна. Прогон выполнен при масштабе Windows 125% и рабочей области 2048×1232.

UI smoke не автоматизирует ввод реального письма и SMTP-доставку. Код восстановления проверяется на уровне базы и HTTP-клиента с подменённым ответом Mail API. Реальная отправка через SMTP и получение письма в почтовом ящике **не проверялись в этом прогоне**; для такой проверки требуется отдельный Mail API с действующими SMTP-настройками и тестовый адрес получателя.

## Публикация

Сборка автономного Windows x64 приложения выполняется для проекта приложения, а не для всего solution:

```powershell
dotnet publish TravelReady/TravelReady.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

Автономный Windows x64 пакет r9 пересобран 02.10.2026 после обновления интерфейса и входа. Публикация не устанавливает SQL Server LocalDB и не включает секреты Mail API, SMTP или WeatherAPI.
